Layered System Architecture

The system follows a strict layered Spring architecture ensuring separation of concerns, transactional integrity, and strong typing:

Client / Thymeleaf Web UI / Swagger UI

Core Clinical Business Rules

1. 90-Day Donor Recovery Gap

Statutory whole blood donation recovery period. A donor who gave blood within the last 90 days is strictly blocked from donation. The system tracks lastDonationDate, nextEligibleDate, and remainingDays.

2. 42-Day Blood Unit Shelf Life

Every registered whole blood unit is assigned an expiry date exactly 42 days from collection (collectionDate.plusDays(42)).

3. 7-Day Near-Expiry Cutoff Window

Units with ≤ 7 days remaining before expiration are categorized as NEAR_EXPIRY. The safe stock aggregator and FEFO issue query automatically exclude these units from available inventory.

4. First-Expire, First-Out (FEFO) Allocation

When issuing blood for a patient requisition, the system queries safe available units ordered by expiryDate ASC, id ASC, ensuring the oldest viable safe unit is dispatched first to minimize waste.

5. Double Issue & Atomic Integrity Prevention

Once issued, a BloodUnit immediately transitions to ISSUED status and is linked to an IssueRecord via a unique database foreign key constraint, preventing double issuing.

Database Entities & Relationships

donors

PK: id
Unique: donor_code, email, phone
Fields: name, blood_group, dob, gender, active

donations

PK: id
FK: donor_id → donors(id)
Unique: donation_code
Fields: donation_date, units_created, notes

blood_units

PK: id
FK: donation_id → donations(id)
Unique: unit_code
Fields: blood_group, collection_date, expiry_date, status

issue_records

PK: id
FK/Unique: blood_unit_id → blood_units(id)
Unique: issue_code
Fields: patient_name, hospital_name, issue_date

Real Email Notification & Audit Engine

Asynchronous, transaction-safe notification engine using Spring Boot Mail and JavaMailSender:

Feature Configuration Status Operational Description
Email Notifications Configured (Safe Mode) Controls whether real SMTP dispatch is active (via bloodbank.mail.enabled).
SMTP Provider SMTP / Gmail TLS 587 Configured via environment variables (MAIL_HOST, MAIL_PORT). Secrets protected.
Admin Alert Recipient admin@bloodbank.org Receives real-time operational alerts for Near-Expiry (≤ 7d), Expired units, and Issue audits.
Transaction Safety AFTER_COMMIT Safe Emails only fire after successful database commit. SMTP failure never fails donations.
